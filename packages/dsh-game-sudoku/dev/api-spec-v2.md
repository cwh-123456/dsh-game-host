## 1. 难度等级与技巧顺序（冻结）

| level | grade key | 标签 | 判定（最高用到的技巧） |
|---|---|---|---|
| 1 | `easy` | 简单 | 只用唯一候选 / 隐性唯一（naked-single / hidden-single） |
| 2 | `normal` | 普通 | 需要锁定候选（pointing / claiming），不需要更高 |
| 3 | `hard` | 困难 | 需要数对/数组（naked-pair / naked-triple / hidden-pair / hidden-triple），不需要 Wing |
| 4 | `expert` | 专家 | 需要 X-Wing 或 XY-Wing |
| 5 | `hell` | 地狱 | 技巧全试完仍解不动（卡住） |

技巧按以下顺序尝试，**前一级无进展才尝试下一级**；任一级有进展就从第 1 级重新开始：

1. `naked-single`（唯一候选，填数）
2. `hidden-single`（隐性唯一，填数）
3. `pointing` / `claiming`（锁定候选，删候选）
4. `naked-pair` / `naked-triple` / `hidden-pair` / `hidden-triple`（数对/数组，删候选）
5. `x-wing`（行/列各向，删候选） / `xy-wing`（双值格 pivot + 两 pincer，删候选）

- 评级 = 求解过程中**用到的最高 level**；若最终卡住（还有空格且无技巧可用）= `hell`。
- `techniques` = 实际用到的技巧名去重列表，按首次使用顺序（确定、可复现）。
- 技巧实现必须**确定**：格子 0..80、单元 0..26（行 0..8、列 9..17、宫 18..26）、数字 1..9 升序；
  同一技巧一次应用所有可找到的消除/填数（或逐条应用亦可，但必须每次同样顺序），结果必须逐次一致。
- 求解器只做候选掩码（`number[81]` 每格 9-bit），不猜数；不允许回溯。
- 生成器/评级器在 **dev 侧**（node）；运行时 client.js 不含生成器、不含求解器。

## 2. 离线题库 `dev/bank.json`（权威产物）

```json
{
  "version": 2,
  "generatedAt": "2026-10-18T…+08:00",
  "generator": { "seed": 20261018, "attempts": 0, "genMs": 0 },
  "levels": [{ "key": "easy", "label": "简单", "level": 1, "count": 40 }, …],
  "puzzles": [{
    "id": "easy-1a2b3c",            // grade 前缀 + givens 的 FNV-1a32 base36 哈希（稳定）
    "grade": "easy",
    "givens": "530070000…",          // 81 位字符串，'0'=空
    "solution": "534678912…",        // 81 位字符串（仅 dev 产物，不内联）
    "clues": 40,
    "techniques": ["naked-single", "hidden-single"]
  }]
}
```

- 每档 **30~50 题**；建议配额：easy 40 / normal 40 / hard 40 / expert 40 / hell 30（共 190）。
- 每题必须：唯一解（`countSolutions(givens,2)===1`）、`grade===目标档`、
  `solution` 是唯一解、givens 无重复冲突、同一档内 id/题面不重复。
- `id` 由题面决定：同题面 → 同 id；重建题库时旧存档能匹配到的题继续有效，匹配不到就丢弃。

## 3. 题内联格式（client.js 中由 gen-bank 自动写入，勿手改）

client.js 顶部常量区固定含标记块：

```js
  /* ==== SUDOKU PUZZLE BANK: BEGIN (generated by dev/gen-bank.mjs, do not edit) ==== */
  const PUZZLE_BANK = {
    version: 2,
    generatedAt: '2026-10-18T…',
    levels: [{ key: 'easy', label: '简单', level: 1 }, …],
    puzzles: [
      { id: 'easy-1a2b3c', grade: 'easy', givens: '530070000…' },
      …
    ],
  }
  /* ==== SUDOKU PUZZLE BANK: END ==== */
```

- 内联只含 `id/grade/givens`（+ version/generatedAt/levels），**不含 solution/techniques**。
- 顺序：按 levels 顺序、同档内按 id 排序（稳定）。总大小预计 ~20–30KB。
- 内联块必须与 `dev/bank.json` 的 id/grade/givens **逐题一致**（test-grade 会校验）。

## 4. `dev/lib/techniques.mjs`（node 侧共享库）

导出（ESM）：

```js
LEVELS                       // [{key,label,level}]
TECHNIQUE_LEVEL              // { 'naked-single':1, …, 'xy-wing':4 }
parseGrid(givens)            // string|number[] -> number[81]
gridToString(grid)           // -> 81 位字符串
countSolutions(givens, limit=2) // 位掩码 MRV，数到 limit；非法输入抛 TypeError
solve(givens)                // 首解 number[81] | null
computeConflicts(grid)       // number[81] 0/1
gradePuzzle(givens)          // { grade, level, solved, techniques, solution, stuck, steps }
generateFullGrid(rng)        // 随机完整盘 number[81]
makeRng(seed)                // mulberry32
```

`gradePuzzle` 必须满足 §1；`steps` 记录 `{level, technique}` 首次使用列表（可省略细节）。
额外要求：`gradePuzzle` 对合法唯一解题必须给出 `solution` 且等于 `solve()` 结果；对坏题
（无解/多解）返回 `{ grade:'invalid', solved:false }` 或抛 TypeError（gen-bank 会先验唯一解）。

## 5. `dev/gen-bank.mjs`

`node dev/gen-bank.mjs`：

1. 对每个目标档循环生成直到配额：
   - 用 `makeRng(seed)`（固定 base seed，便于复现）生成完整盘；
   - 打乱 81 格逐个挖空，每挖一格保持唯一解（`countSolutions(...,2)===1`）；
   - 每成功挖一格后 `gradePuzzle` 当前题：
     * grade === 目标档 → 收题（记录 clues/techniques/solution）；
     * grade 比目标档难 → 放弃该次尝试（重新换盘/换挖空顺序）；
     * 比目标档简单 → 继续挖；
   - `hell` 档：一直挖到挖不动（唯一解约束下），grade 为 hell 才收；否则重试；
   - 达到配额或尝试上限（比如每档 20000 次）停止；不足配额则非零退出并打印原因。
2. 每题复核：唯一解、solution 合法且与 givens 一致、两次 `gradePuzzle` 结果一致（评级稳定）、
   id 不重复、同档题面不重复。
3. 把 `bank.json` 写到**临时目录**（node 在 workspace 写盘被沙箱拒绝）：
   `path.join(os.tmpdir(), 'dsh-sudoku-bank-<timestamp>', 'bank.json')`；
   若 client.js 中已有 BANK 标记块，同时读 client.js、把内联块替换为新题库，
   写 `client.banked.js` 到同临时目录。打印：临时目录、各档 stats（尝试/接受/耗时/提示数分布）、
   生成总耗时、bank 字节数、内联字节数、唯一解复核结果。
4. 校验失败或配额不足 → exit 1。

**把临时产物搬进 workspace**（沙箱技巧，Lead 也可代做）：

```powershell
Copy-Item "<临时目录>\bank.json" "packages\dsh-game-sudoku\dev\bank.json" -Force
Copy-Item "<临时目录>\client.banked.js" "packages\dsh-game-sudoku\client.js" -Force
```

`pwsh` 的 workspace 写被 ACL 拒绝时，用工具参数 `sandbox_permissions: "danger-full-access"` 重试
（一次只做上述 copy，附 justification）。若仍失败，把临时路径发给 Lead 代搬。

## 6. `dev/test-grade.mjs`

`node dev/test-grade.mjs`，读取 `dev/bank.json` + client.js 内联块：

1. 题库结构：5 档、每档 30~50、id 唯一、题面唯一、givens 合法无冲突。
2. **每题独立重评级 3 次**：grade 每次都等于题库记录的目标档、techniques 列表逐次相同、
   solution 与 `solve()` 一致；全部稳定才算 PASS。
3. 唯一解：`countSolutions(givens,2)===1`（用 lib 的求解器；可另写一版简单候选集求解器做交叉复核）。
4. **100 题随机生成验证唯一解率**：随机 seed 生成完整盘并挖到唯一解停止（用 lib 的挖空函数），
   对 100 道题跑 `countSolutions===1`，输出通过率（应为 100/100）。
5. **技巧覆盖统计**：按 grade 汇总 techniques 出现次数；断言：
   - easy 至少用到 singles；normal 至少用到 pointing/claiming 之一；
   - hard 至少用到 pair/triple 之一；expert 至少用到 x-wing 或 xy-wing 之一；
   - hell 至少有一题是「技巧耗尽仍卡住」；打印覆盖表（报告直接引用）。
6. 内联一致性：内联 id/grade/givens 与 bank.json 完全一致、数量一致。
7. 打印 `PASS n / FAIL 0` 与非零退出规则。

## 7. 运行时 `client.js` v2

- **移除**运行时的 `generatePuzzle / countSolutions / solve`（不再生成任何题）；保留
  `computeConflicts / isSolved / countEmpty / formatTime` 等轻量工具。
- 启动：`loadSavedState()` 有效 → 恢复当前题（题库按 `puzzleId` 取 givens），**绝不换题**；
  无/坏存档 → 用默认档 `normal` 抽一道**优先未玩过**的题。
- `pickPuzzle(grade, played, rng)`：该档中 `id ∉ played` 的题里均匀随机（无 rng 用 Math.random）；
  该档全都玩过 → 在该档全部题里随机。新题开始后把 id 加入 `played`（上限 500，丢最旧）。
- 难度 UI：5 个 chip（简单/普通/困难/专家/地狱），active = 当前题 grade；点不同档：
  有进度先确认，确认后抽该档未玩过的新题；无进度立即换题。
- 存档 key 不变：`localStorage['dsh.game.sudoku.v1']`，`schemaVersion: 2`：

```js
{
  schemaVersion: 2,
  puzzleId: 'normal-xxxx',
  grade: 'normal',
  entries: number[81],   // 玩家层：0=空；给定格必须 0（恢复时强制 0）
  notes: number[81],     // 草稿 bitmask 0..511；给定格/有值格必须 0（恢复时归零）
  elapsed: number,       // 已用毫秒
  played: string[],      // 已玩过的 puzzleId（额外字段，用于优先未玩过；上限 500）
  winAcked: boolean      // 额外字段：胜利遮罩是否已关闭（可选，缺省 false）
}
```

- `sanitizeSave(raw)`：`schemaVersion===2`、`puzzleId` 在题库中、`grade` 与题库一致、
  entries/notes 长 81 且整数范围合法、给定格 entries 归 0、有值/给定格 notes 归 0、
  elapsed 有限并 clamp `0..604800000`、played 过滤为题库中存在的 id 且 ≤500、winAcked 布尔化；
  任一结构性失败返回 null。**旧 v1 存档（无 puzzleId）自动丢弃并开新题**（不报错）。
- 状态机/交互/计时/撤销/确认遮罩/胜利/窗口太小/错误边界：沿用 v1（见 `dev/api-spec.md` §4、§7、§8），
  仅把「生成新题」换成「抽题库题」，`board = givens + entries`，`won=isSolved(board)`。
- 计时、落盘时机、ResizeObserver、根节点键盘、无全局 keydown 等 v1 约束全部保留。
- 难度 chip 文案来自 `PUZZLE_BANK.levels`；胜利遮罩显示当前 grade 标签。

### 测试 seam v2（仅 `window.__DSH_GAME_SUDOKU_TEST__===true`）

导出（保留 v1 中仍适用的名称）：


## 8. `dev/test-logic.mjs`（client 侧自测，node）

- window 桩 + test seam；覆盖：
  1. 常量/题库：5 档、每档 30~50、id 唯一、内联 givens 合法；每档抽题 grade 匹配。
  2. `pickPuzzle` 未玩过优先：played 为空取一题；played=该档全部 id 时仍能返回同档题；
     同 played 集合多次抽取分布不为单一 id（用 seeded rng 检查 >1 种）。
  3. `createState`：board=givens、空 entries/notes、计时 0、played 含当前题。
  4. 输入/草稿/擦除/撤销/胜利锁定：沿用 v1 用例（board 改为 givens+entries）。
  5. 重开同题；`newPuzzle` 换题且优先未玩过、grade 正确、计时归零、played 累加。
  6. 难度切换逻辑（UI 层由 Lead Chromium 验收；这里测 `newPuzzle` 的 grade 参数/非法 grade 回退）。
  7. 计时 pause/resume/elapsed。
  8. 存档：serialize 字段 = {schemaVersion:2,puzzleId,grade,entries,notes,elapsed,played,winAcked}；
     sanitize→state→serialize 往返；坏档矩阵（无 puzzleId/未知 id/grade 不符/长度错/越界/
     给定格 entries 非 0（归 0 或拒绝按规格）/notes 越界/elapsed 非数/played 坏值）；
     500 次随机篡改不抛；`loadSavedState` 坏 JSON/localStorage 抛错 → null；
     **恢复同一题**：构造存档 → load → puzzleId/givens 不变；不存在的 id → null（不抽新题）。
  9. `formatTime`、`computeConflicts`、`isSolved` 边界。
- PASS/FAIL 计数，失败非零退出；只用 node 内置模块（可 `import './lib/techniques.mjs'` 做题库唯一解/评分交叉验证）。
